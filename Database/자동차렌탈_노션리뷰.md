# 노션 리뷰 — 20261015 DB 팀과제 (자동차 렌탈)

> 리뷰 대상: 노션 공개 페이지 `20261015 DB 팀과제`
> 리뷰 시점: 페이지 버전 499 기준 / DBMS: MySQL 8 가정
> 리뷰 범위: 요구사항분석 · 논리설계 · 물리설계(CREATE) · 목데이터(INSERT) · 쿼리문 15개

---

## 0. 한눈에 보는 결론

| 섹션 | 상태 | 한줄 평가 |
| --- | --- | --- |
| 요구사항분석 | 🟢 양호 | 개체·속성·관계를 문장으로 잘 도출 |
| 논리설계 | 🟡 보완 필요 | 표 10개는 채워졌으나 **car_location 컬럼 누락**, `car_num`에 `auto_increment` 오지정 |
| 물리설계(CREATE) | 🔴 정리 필요 | **CREATE 3벌 공존** + 깨진 ALTER 패치문, 논리설계와 컬럼명 불일치 |
| 목데이터(INSERT) | 🔴 정리 필요 | **INSERT 2벌 공존**, 그중 1벌은 어떤 CREATE와도 안 맞아 실행 불가 |
| 쿼리문 15개 | ⚫ 미작성 | 제출물의 핵심 항목이 비어 있음 |

**총평**: 요구사항 → 논리설계까지는 방향이 맞습니다. 다만 **물리설계 단계에서 스키마가 3개로 갈라지고, 논리설계와 컬럼명·타입이 어긋나며, 목데이터가 두 스키마를 섞어서** "하나의 일관된 최종 스키마"가 없는 상태입니다. 제출 전 **① 최종 스키마 1개 확정 → ② 논리설계 표를 거기에 맞춤 → ③ INSERT 1벌로 통일 → ④ 쿼리 15개 작성** 순으로 정리하는 것을 권합니다.

## 1. 잘한 점 (유지할 부분)

1. **요구사항을 자연어 문장으로 먼저 정리**하고 거기서 개체/속성/관계를 뽑은 흐름이 교과서적입니다.
2. **M:N 관계를 브릿지 테이블로 인식**했습니다.
   - 차량 ↔ 차고지 → `car_location`
   - 사용자 ↔ 차량 → `rentals`
3. 테이블 **10개**로 "최소 8개" 요건을 충족합니다.
4. 목데이터를 실제 값으로 **두 벌** 만들어 값 삽입을 연습한 점은 좋습니다.
5. 특히 `-- 렌트카 DB (FK, 타입 정리 버전)` 코드블록은 **FK 제약과 `CHECK (rent_end > rent_start)`까지** 정리되어 있어 가장 완성도가 높습니다. → **이 버전을 최종안으로 채택**하는 것을 권장합니다.

## 2. 🔴 심각 — 반드시 고쳐야 할 것

### 2-1. `car_location`에 `garage_id`가 없음 (논리설계 표)

논리설계 `car_location` 표의 컬럼이 **`loca_id(PK)`, `car_num(FK)`** 두 개뿐입니다.
그런데 요구사항은 "차량 : 차고지 = M:N"이고, 목적은 **차고지 위치별로 차량을 조회**하는 것입니다.
`garage_id`가 없으면 **어느 차고지에 있는 차량인지 저장할 수 없습니다.**

- 물리설계(`rentcar` 버전)에는 `car_location (loca_id, car_id, garage_id, assigned_at)`로 **제대로** 들어가 있습니다.
- 즉 **논리설계 표만 틀렸습니다.** 표를 다음처럼 수정하세요.

| 컬럼 | loca_id (PK) | car_id (FK) | garage_id (FK) | assigned_at |
| --- | --- | --- | --- | --- |
| 타입 | INT AUTO_INCREMENT | INT NOT NULL | INT NOT NULL | DATETIME |

추가로 같은 차량·차고지 중복을 막으려면 `UNIQUE(car_id, garage_id)`를 걸어 두는 것이 좋습니다.

### 2-2. CREATE문이 3벌 공존 + 깨진 ALTER 패치문

물리설계 구역에 코드블록이 3개 있습니다.

| # | 시작 문구 | 상태 |
| --- | --- | --- |
| 1 | `-- 스키마 알아서 만들어서 추가하세요!!` | 🔴 CREATE엔 FK가 없고, 뒤에 **ALTER로 FK를 억지로 붙이는 디버깅 흔적** |
| 2 | `-- 렌트카 DB (FK, 타입 정리 버전)` | 🟢 **가장 완성도 높음 (최종안 권장)** |
| 3 | `-- 자동차 렌트 테이블 생성` | 🟡 FK 없음, `owner_id varchar(50) not null` 등 타입 혼선 |

1번 블록의 ALTER 패치문은 **타입 불일치로 실제로 실패**합니다.

```sql
-- (노션 1번 블록에서 발췌)
ALTER TABLE owner MODIFY owner_id VARCHAR(50);
ALTER TABLE user  MODIFY owner_id VARCHAR(50);
ALTER TABLE user  MODIFY u_id INT UNSIGNED AUTO_INCREMENT;   -- PK를 이미 자식이 참조 중이면 실패
ALTER TABLE owner MODIFY u_id INT UNSIGNED;
```

문제점:
- 한쪽은 `VARCHAR(50)`, 다른 쪽은 `INT UNSIGNED`로 **왔다갔다** 하며, FK는 양쪽 타입이 **완전히 동일**해야 합니다.
- **이미 데이터나 FK가 걸린 뒤 `MODIFY`로 PK 타입을 바꾸는 방식**은 거의 항상 실패합니다.
- 해결: **CREATE 시점에 타입을 처음부터 일치**시키고, 이런 ALTER 패치문은 **삭제**하세요.

> 정리: 1번·3번 블록은 지우고 **2번(`rentcar`) 하나만 남기는 것**을 권장합니다.

### 2-3. 목데이터(INSERT)가 스키마와 불일치

목데이터 토글 안에 INSERT가 2벌 있습니다.

| # | 대상 컬럼 | 어떤 CREATE와 맞는가 |
| --- | --- | --- |
| A | `user_id, password, name, email, phone, license_number, owner_id` | 🔴 **어떤 CREATE와도 불일치 → 실행 불가** |
| B | `(u_name, user_id, u_pw, u_email, u_phone, u_license)` 등 | 🟢 `rentcar` 버전과 일치 |

A벌은 컬럼명이 영어(`password`, `name`, `license_number`)이고, `rental`/`payment`(단수형) 테이블을 씁니다.
최종 스키마(`rentcar`)는 `u_pw`, `u_name`, `u_license`, `rentals`, `payments`(복수형)를 쓰므로 **A벌은 전부 오류**입니다.

> 정리: **B벌("렌트카 DB 연습용 목데이터")만 남기고**, 테이블명이 `rentals`/`payments`인지 최종 스키마와 최종 확인하세요.

### 2-4. `NOT NULL`인데 `NULL`을 넣는 모순

3번 CREATE 블록은 `owner_id varchar(50) NOT NULL`인데, A벌 INSERT는 `user02`, `user04`에 `owner_id = NULL`을 넣습니다.
→ `Column 'owner_id' cannot be null` 오류. **NOT NULL과 데이터가 서로 모순**입니다. 둘 중 하나를 고쳐야 합니다(아래 3-1 참고).

## 3. 🟡 논리설계 ↔ 물리설계 불일치 (컬럼명·타입)

논리설계 표와 `rentcar` CREATE를 대조하면 컬럼명이 어긋납니다.

| 테이블 | 논리설계 표 | rentcar CREATE | 판정 |
| --- | --- | --- | --- |
| user | `u_id, u_name, user_id, u_pw, u_email, u_phone, **owner_id**, u_license` | `u_id, u_name, user_id, u_pw, u_email, u_phone, u_license` (**owner_id 없음**) | 🔴 `owner_id` 유무 불일치 |
| car | `car_id, car_num, car_type, owner_id` | `car_id, car_num, car_type, owner_id` | 🟢 (단 `car_num` 길이 10 vs 20) |
| car_location | `loca_id, **car_num**` (garage_id 없음) | `loca_id, **car_id**, garage_id, assigned_at` | 🔴 컬럼 누락 + 이름 불일치 |
| maintenance | `m_id, **car_num**, m_his, m_price` | `m_id, **car_id**, m_his, m_price` | 🟡 `car_num` vs `car_id` |
| rentals | `rental_id, u_id, car_id, rent_start, rent_end` | 동일 | 🟢 |
| payments | `payment_id, rental_id, amount, status, method, paid_at` | 동일 | 🟢 |
| review_to_car | `review_car_id, u_id, **car_number**, content` | `review_car_id, u_id, **car_id**, content` | 🟡 `car_number` vs `car_id` |
| review_to_user | `review_user_id, owner_id, u_id, content` | 동일 | 🟢 |

**핵심 원칙**: 자식 테이블의 FK 컬럼은 **부모 이름을 그대로** 따라가는 게 안전합니다.
부모 `car`의 PK가 `car_id`이면, 자식 FK도 `car_id`로 통일하세요 (`car_num`/`car_number` 혼용 제거).

### 3-1. `user.owner_id` 순환 참조 문제 (설계 결정 필요)

- 논리설계 `user`에는 `owner_id(fk)`가 있어 **user → owner** 를 참조합니다.
- 그런데 `owner`에는 `u_id(fk)`가 있어 **owner → user** 를 참조합니다.
- 두 테이블이 **서로를 참조(순환)** 합니다. 이대로면 `CREATE`도, 목데이터 `INSERT`도 순서 문제로 실패합니다.

**해결 방법(택 1)**

| 방법 | 설명 | 평가 |
| --- | --- | --- |
| (권장) `user.owner_id` 제거 | 소유주 여부는 `owner.u_id`의 **1:1**로만 표현. 순환이 사라져 가장 단순 | 👍 권장 |
| `user.owner_id` 유지 | 테이블은 user를 FK 없이 먼저 생성 → owner 생성 → `ALTER`로 FK 추가. 데이터는 user를 `owner_id NULL`로 넣고 → owner 넣고 → `UPDATE` | 가능하나 복잡 |

`rentcar` 버전은 이미 **`user.owner_id`를 제거**했으므로 (권장안과 동일) 순환이 없습니다.
다만 그러면 **요구사항 문장 "사용자는 …소유자여부(fk)를 입력"** 과 어긋나므로,
요구사항 문장을 **"소유주 여부는 owner 테이블의 u_id(fk)로 관리한다"** 로 다듬는 것을 권합니다.

## 4. 🟡 논리설계 표의 세부 오류

| 위치 | 문제 | 수정 |
| --- | --- | --- |
| `car_location` "기본값" 행 | `car_num`에 `auto_increment` 표기 | **FK 컬럼은 auto_increment 금지** → 공란 |
| `maintenance` "기본값" 행 | `car_num`에 `auto_increment` 표기 | FK이므로 공란 |
| `user` "면허증 여부" 라벨 | 값은 "면허증 **번호**"인데 "여부"로 표기 | 라벨을 "면허증번호"로 |
| `user` 컬럼명 | `u_id`(PK)와 `user_id`(로그인 아이디)가 헷갈림 | 주석/라벨 명확화 (예: `u_id`=회원번호, `user_id`=로그인ID) |
| `review_to_car`, `review_to_user` PK | `auto_increment` 미표기(고정값) | `AUTO_INCREMENT` 권장 |
| `payments.amount`, `maintenance.m_price` | `int` (금액) | 금액은 `DECIMAL(10,2)` 권장 |
| `garage.adr` | 논리설계 varchar(20) / rentcar varchar(200) | 주소는 `VARCHAR(200)` 권장 |

## 5. ⚫ 누락된 제출물

1. **쿼리문 15개** — 현재 완전히 비어 있습니다. 요구 조건:
   - **그룹핑(GROUP BY)**, **조인(JOIN)**, **부질의(서브쿼리)**, **탑앤(TOP-N)** 이 모두 포함되어야 함
   - MySQL 기준 탑앤은 `LIMIT n`
2. **물리설계 "테이블 정의서(표)"** — 지금은 CREATE 코드만 있고 **표 형태 정의서가 없습니다.**
   논리설계 표를 재활용하되 "테이블명/컬럼/타입/PK/FK/NULL/제약" 열을 갖춘 표를 별도로 두세요.

## 8. 권장 최종 스키마 (요약 스케치)

```sql
CREATE SCHEMA IF NOT EXISTS rentcar;
USE rentcar;

CREATE TABLE user (          -- owner_id를 두지 않아 순환 FK 제거
  u_id      INT AUTO_INCREMENT PRIMARY KEY,
  u_name    VARCHAR(30)  NOT NULL,
  user_id   VARCHAR(20)  NOT NULL UNIQUE,   -- 로그인 아이디
  u_pw      VARCHAR(255) NOT NULL,
  u_email   VARCHAR(100) NOT NULL UNIQUE,
  u_phone   VARCHAR(20)  NOT NULL UNIQUE,
  u_license VARCHAR(20)  NOT NULL UNIQUE
);

CREATE TABLE owner (
  owner_id INT AUTO_INCREMENT PRIMARY KEY,
  u_id     INT NOT NULL UNIQUE,
  bu_num   VARCHAR(30) NOT NULL UNIQUE,
  ow_num   VARCHAR(30) NOT NULL UNIQUE,
  FOREIGN KEY (u_id) REFERENCES user(u_id)
);

CREATE TABLE garage (
  garage_id INT AUTO_INCREMENT PRIMARY KEY,
  adr       VARCHAR(200) NOT NULL
);

CREATE TABLE car (
  car_id   INT AUTO_INCREMENT PRIMARY KEY,
  car_num  VARCHAR(20) NOT NULL UNIQUE,
  car_type VARCHAR(30) NOT NULL,
  owner_id INT NOT NULL,
  FOREIGN KEY (owner_id) REFERENCES owner(owner_id)
);

CREATE TABLE car_location (   -- 차량 ↔ 차고지 브릿지 (garage_id 필수!)
  loca_id     INT AUTO_INCREMENT PRIMARY KEY,
  car_id      INT NOT NULL,
  garage_id   INT NOT NULL,
  assigned_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE (car_id, garage_id),
  FOREIGN KEY (car_id)    REFERENCES car(car_id),
  FOREIGN KEY (garage_id) REFERENCES garage(garage_id)
);

CREATE TABLE maintenance (
  m_id    INT AUTO_INCREMENT PRIMARY KEY,
  car_id  INT NOT NULL,
  m_his   VARCHAR(200) NOT NULL,
  m_price DECIMAL(10,2) NOT NULL,
  FOREIGN KEY (car_id) REFERENCES car(car_id)
);

CREATE TABLE rentals (
  rental_id  INT AUTO_INCREMENT PRIMARY KEY,
  u_id       INT NOT NULL,
  car_id     INT NOT NULL,
  rent_start DATETIME NOT NULL,
  rent_end   DATETIME,
  FOREIGN KEY (u_id)   REFERENCES user(u_id),
  FOREIGN KEY (car_id) REFERENCES car(car_id)
);

CREATE TABLE payments (
  payment_id INT AUTO_INCREMENT PRIMARY KEY,
  rental_id  INT NOT NULL,
  amount     DECIMAL(10,2) NOT NULL,
  status     VARCHAR(20) NOT NULL,
  method     VARCHAR(20),
  paid_at    DATETIME,
  FOREIGN KEY (rental_id) REFERENCES rentals(rental_id)
);

CREATE TABLE review_to_car (
  review_car_id INT AUTO_INCREMENT PRIMARY KEY,
  u_id          INT NOT NULL,
  car_id        INT NOT NULL,
  content       VARCHAR(1000) NOT NULL,
  FOREIGN KEY (u_id)   REFERENCES user(u_id),
  FOREIGN KEY (car_id) REFERENCES car(car_id)
);

CREATE TABLE review_to_user (
  review_user_id INT AUTO_INCREMENT PRIMARY KEY,
  owner_id       INT NOT NULL,
  u_id           INT NOT NULL,
  content        VARCHAR(1000) NOT NULL,
  FOREIGN KEY (owner_id) REFERENCES owner(owner_id),
  FOREIGN KEY (u_id)     REFERENCES user(u_id)
);
```
