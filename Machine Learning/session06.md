# 세션 06: 분류 모델 (Classification) — 지도학습

- 데이터의 피쳐(문제)를 바탕으로 해당 데이터가 어떤 class에 속할지 예측하는 것
- ex) 암이냐 아니냐? 나이, 키&몸무게, 조직검사 수치를 보고 암여부를 예측해볼래?
- ex) 악성 댓글 탐지: 문제 — 특정 단어가 있는가?

## Decision Tree (스무고개 알고리즘)

- 피쳐를 바탕으로 분할 기준을 만들어서 class를 분류하는 트리구조
- ex) 몸집이 작나요? 날개가 있나요? 물에서 사나요? → 날 수 있나요?로 더 명확한 분류 (매/펭귄)
- ⇒ 손실(loss)은 모델이 학습 후 예측을 수행했을 때, 틀린 정도를 측정하는 값
- 손실 값이 클수록 모델이 학습 방향을 바꿔야 한다는 신호를 주는 것
- 불순도 예시: 독수리: 15, 펭귄: 20, 사람 12명
  - "동물이냐?" → 펭귄, 독수리/사람 분리: 불순도 낮음
  - "날개있냐?" → 독수리: 펭귄 분리: 불순도 높음
- 더 세밀하게 분류 기준을 세우게 되고 → 과적합이 높아진다.

## 전처리 관련 유의점

- NaN 결측치가 데이터에 포함되면 학습 불가 → 값을 채우거나 삭제 필요
- 문자 형태도 모델이 인식 불가 ⇒ 숫자로 바꾸거나 삭제 필요
- 정답과 문제를 분리하는 작업 필요. 답이랑 같이 모델 학습에 들어가면 컨닝하는 것과 다름없음

## 과적합 (Overfitting)

- 과적합: 학습 데이터가 지나치게 최적화되어, 새로운 데이터에 대한 일반화 능력이 떨어진다.
- 데이터를 외워버려, 응용문제가 불가능하다.
- ex) 강아지 야외 1·실내 9, 고양이 야외 9·실내 1일 때, 강아지·고양이만 분류해야 하는데 사진의 배경(실내=강아지, 야외=고양이)까지 판단할 수 있음

## 앙상블 (Ensemble) 기법

### (1) Voting: 서로 다른 모델을 동일한 데이터로 학습시켜 오버피팅 방지

- 클래스 비교 (Hard voting) 해서 결과도출
- 확률값으로 비교 (Soft voting) 해서 결과도출
- #여러 명에게 시험문제를 풀게 한 후, 답을 모아서 다수결로 정한다

### (2) Bagging (Bootstrap Aggregating): 동일한 모델들을 서로 다른 데이터로 학습시켜 오버피팅을 방지하고 분산을 높인다

- → decision tree를 여러 개 쓴다
- ex) 대표적인 모델: Random Forest ⇒ 무작위 샘플링 (Bootstrap Sampling)
  1. training data에서 random sampling하여 X_b, y_b를 고름 (ex. 1,000개 중 100개 sampling)
  2. X_b, y_b를 이용하여 ID3 알고리즘으로 decision tree 구성
  3. B개의 tree가 만들어질 때까지 1, 2 반복
  4. B개의 모든 tree로 classification 후 majority vote로 결정
  5. Bias를 유지하며 Variance를 줄인다
- 부트스트랩 샘플링: 중복 허용하면서 랜덤하게 뽑아서 여러 개의 학습 데이터셋을 만든다. (ex) 공이 100개 있다 가정하면 10개 뽑고 복원한 후, 10개 뽑고..)
- 개별 모델 학습: DT를 각각 부트스트랩 샘플링에 학습시킨다
- 결과 결합 (Aggregating): 여러 모델 예측을 다수결로 설정 → 모델 불안정성 줄임, 과적합 방지
- ⇒ 여러 학생한테 시험을 풀게 한 후, 정답을 다수결로 정하는 것과 유사

### (3) Random Forest (Bagging + Decision Tree + Feature Random)

- Decision Tree에 포함될 attribute들을 random하게 선정한다
- 모든 attribute로 트리 만들면 매우 강한 attribute가 모든 tree에 항상 포함되는 것을 막기 위한 방법
  - (ex. 30개 attribute 중 10개만 random selection) — 트리 분할 시 랜덤하게 선택된 일부 특성만 사용

**bias와 variance**

- bias (편향) — 언더핏: 모델이 단순해서 데이터의 복잡한 패턴을 인식 잘 못함
- variance (분산) — 오버핏: 모델이 데이터에 너무 민감, 새로운 데이터에는 성능이 떨어짐

**Voting과 Bagging 차이점**

- Voting: 데이터셋의 크기가 작을 때, 결과를 해석하는 경우
- Bagging: 데이터셋의 크기가 클 때, 노이즈(이상치)에 강한 모델이 필요할 때

### (4) Boosting: 모델을 순차적으로 학습하면서 잘못 예측한 부분에 가중치를 더해가는 방식 ⇒ 이전 모델이 틀린 부분을 집중적으로 학습

- AdaBoost: 잘못 분류한 데이터에 가중치를 부여해서 순차적으로 학습한 뒤, 학습된 모델들을 통합 ⇒ 가중치 부여방식은 오류율
- GradientBoost: 가중치 부여방식 = 경사하강법
- XGBoost: GradientBoost의 느린 속도 개선 (파이썬 패키지, 속도 빠름) — 병렬 처리, 가지 치기, 규제 적용
- LightGBM: 리프 중심 분할로 학습 속도를 단축시키고 예측 성능 향상 ⇒ 손실 높은 리프를 기준으로 분할
- CatBoost (Category boost): 범주형 데이터를 기존과 다른 방식으로 처리

**DT → Ensemble: Bagging / Boosting**

- Random Forest (병렬 학습, 과적합에 매우 강함) / Gradient Boosting (직렬·순차 학습, 정확도가 매우 높음)

**배깅 vs 부스팅 비교**

| 구분      | 배깅 (Random Forest 포함)          | 부스팅 (Gradient Boosting 등)     |
| --------- | ---------------------------------- | --------------------------------- |
| 학습 방식 | 병렬 (여러 모델을 한 번에)         | 순차 (하나씩 차례대로)            |
| 핵심 원리 | 여러 의견을 골고루 듣기 (집단지성) | 틀린 문제를 집중 공략 (오답 노트) |
| 목표      | 과적합 방지 (안정성)               | 정확도 향상 (성능)                |
| 속도      | 빠름 (동시 학습 가능)              | 상대적으로 느림 (앞 모델 대기)    |

- Voting = 다른 알고리즘을 묶는 방법
- Bagging = 같은 알고리즘을 병렬로 여러 개 학습 → 평균/투표
- Boosting = 약한 모델을 순차적으로 연결해서 점점 강화
