# 세션 06: 분류 모델 (Classification) — 지도학습

<!-- session-nav -->
**이동:** [← 세션 05](./session05.md) · [세션 07 →](./session07.md)

- 데이터의 feature(특성/문제)를 바탕으로 해당 데이터가 어떤 class(클래스/정답 종류)에 속할지 예측하는 것
- 예) 암이냐 아니냐? 나이, 키·몸무게, 조직검사 수치를 보고 암 여부를 예측해 볼까?
- 예) 악성 댓글 탐지: 문제 — 특정 단어가 있는가?

> **이 세션이 하는 일 (쉬운 말)**  
> 지난 시각화에서 “데이터를 눈으로 보는 법”을 배웠다면,  
> 오늘은 **“어느 쪽인지 가르는 법”**(분류, Classification)으로 들어갑니다.  
> **Decision Tree(결정 트리)** 로 스무고개처럼 나누는 법을 보고,  
> 한 나무가 외워 버리는 **과적합**을 막기 위해  
> **Voting / Bagging / Boosting** 같은 **앙상블(Ensemble)** 을 비유로 익힙니다.

> **쉽게 이해하기**  
> **분류(classification)** 는 “예/아니오”, “A/B/C” 같은 **클래스(class, 정답 종류)** 를 맞추는 일입니다.  
> **피처(feature, 특성)** 는 나이·키처럼 모델에 넣는 힌트입니다.  
> 학습 전에 문제(X)와 정답(y)을 나눠야 합니다. 정답이 입력에 섞이면 **컨닝**과 같습니다.

---

## Decision Tree (스무고개 알고리즘)

- feature를 바탕으로 분할 기준을 만들어서 class를 분류하는 트리 구조
- 예) 몸집이 작나요? 날개가 있나요? 물에서 사나요? → 날 수 있나요?로 더 명확한 분류 (매/펭귄)
- ⇒ **손실(loss)** 은 모델이 학습 후 예측을 수행했을 때, 틀린 정도를 측정하는 값
- 손실 값이 클수록 모델이 학습 방향을 바꿔야 한다는 신호를 주는 것
- 불순도 예시: 독수리 15, 펭귄 20, 사람 12명
  - "동물이냐?" → 펭귄·독수리 / 사람 분리: 불순도 낮음
  - "날개 있냐?" → 독수리·펭귄 분리: 불순도 높음(사람까지 섞일 수 있음)
- 더 세밀하게 분류 기준을 세우게 되고 → 과적합이 높아진다

> **쉽게 이해하기**  
> **결정 트리(decision tree)** 는 예/아니오 질문을 이어 가며 클래스를 고르는 나무입니다. 스무고개와 같습니다.  
> **불순도(impurity)** 는 한 묶음에 종류가 얼마나 섞였는지입니다. 잘 가를수록 불순도가 낮아집니다.  
> **손실(loss)** 은 틀린 정도를 숫자로 본 값입니다.  
> 질문을 너무 잘게 쪼개면 학습 데이터만 외우기 쉽고 **과적합(overfitting)** 으로 이어집니다.

---

## 전처리 관련 유의점

- NaN 결측치가 데이터에 포함되면 학습 불가 → 값을 채우거나 삭제 필요
- 문자 형태도 모델이 인식 불가 ⇒ 숫자로 바꾸거나 삭제 필요
- 정답과 문제를 분리하는 작업 필요. 답이랑 같이 모델 학습에 들어가면 컨닝하는 것과 다름없음

> **쉽게 이해하기**  
> 모델은 빈칸과 글자 문장을 그대로는 쓰기 어렵습니다.  
> **결측치(NaN)** 는 채우거나 지웁니다. 문자는 **인코딩(encoding, 숫자 변환)** 으로 바꿉니다.  
> **피처(X)** 와 **라벨(y)** 을 분리합니다. 라벨이 X에 남으면 새 데이터에서 성능이 무너집니다.

---

## 과적합 (Overfitting)

- 과적합: 학습 데이터가 지나치게 최적화되어, 새로운 데이터에 대한 일반화 능력이 떨어진다
- 데이터를 외워 버려, 응용 문제가 불가능하다
- 예) 강아지 야외 1·실내 9, 고양이 야외 9·실내 1일 때, 강아지·고양이만 분류해야 하는데 사진의 배경(실내=강아지, 야외=고양이)까지 판단할 수 있음

> **쉽게 이해하기**  
> **과적합(overfitting)** 은 학습 데이터만 맞추고 새 데이터에서는 틀리기 쉬운 상태입니다.  
> 강아지·고양이 예에서 배경만 외우면 야외 강아지에서 틀립니다.  
> **일반화(generalization)** 는 본 적 없는 데이터에도 버티는 힘입니다.  
> 트리가 깊어지면 일반화가 약해져 **앙상블(ensemble)** 로 여러 모델을 모읍니다.

---

## 앙상블 (Ensemble) 기법

> **쉽게 이해하기**  
> **앙상블(ensemble)** 은 여러 모델의 예측을 모아 한 번에 결정하는 방법입니다.  
> 한 모델이 틀려도 다른 모델이 맞추면 전체 오류가 줄어듭니다.

### (1) Voting: 서로 다른 모델을 동일한 데이터로 학습시켜 오버피팅 방지

- 클래스 비교 (Hard voting) 해서 결과 도출
- 확률값으로 비교 (Soft voting) 해서 결과 도출
- # 여러 명에게 시험 문제를 풀게 한 후, 답을 모아서 다수결로 정한다

> **쉽게 이해하기**  
> **보팅(voting)** 은 서로 다른 알고리즘을 같은 데이터로 학습시킨 뒤 답을 모읍니다.  
> **Hard voting**은 클래스만 다수결, **Soft voting**은 예측 확률을 평균합니다.

### (2) Bagging (Bootstrap Aggregating): 동일한 모델들을 서로 다른 데이터로 학습시켜 오버피팅을 방지하고 분산을 줄인다

- → Decision Tree를 여러 개 쓴다
- 예) 대표적인 모델: Random Forest ⇒ 무작위 샘플링 (Bootstrap Sampling)
  1. training data에서 random sampling하여 X_b, y_b를 고름 (예: 1,000개 중 100개 sampling)
  2. X_b, y_b를 이용하여 ID3 알고리즘으로 decision tree 구성
  3. B개의 tree가 만들어질 때까지 1, 2 반복
  4. B개의 모든 tree로 classification 후 majority vote로 결정
  5. Bias를 유지하며 Variance를 줄인다
- 부트스트랩 샘플링: 중복 허용하면서 랜덤하게 뽑아서 여러 개의 학습 데이터셋을 만든다. (예: 공이 100개 있다 가정하면 10개 뽑고 복원한 후, 다시 10개 뽑고…)
- 개별 모델 학습: DT를 각각 부트스트랩 샘플링에 학습시킨다
- 결과 결합 (Aggregating): 여러 모델 예측을 다수결로 설정 → 모델 불안정성 줄임, 과적합 방지
- ⇒ 여러 학생한테 시험을 풀게 한 후, 정답을 다수결로 정하는 것과 유사

> **쉽게 이해하기**  
> **배깅(bagging)** 은 같은 알고리즘을 **부트스트랩(bootstrap, 복원 추출)** 으로 만든 여러 데이터로 각각 학습한 뒤 다수결합니다.  
> 보팅은 다른 모델·같은 데이터, 배깅은 같은 모델·다른 샘플입니다.  
> **분산(variance, 예민함)** 을 낮춰 과적합을 줄이는 쪽에 강합니다.

### (3) Random Forest (Bagging + Decision Tree + Feature Random)

- Decision Tree에 포함될 attribute들을 random하게 선정한다
- 모든 attribute로 트리 만들면 매우 강한 attribute가 모든 tree에 항상 포함되는 것을 막기 위한 방법
  - (예: 30개 attribute 중 10개만 random selection) — 트리 분할 시 랜덤하게 선택된 일부 특성만 사용

> **쉽게 이해하기**  
> **랜덤 포레스트(random forest)** 는 배깅으로 만든 트리 숲에, 분할마다 **피처(feature)** 일부만 랜덤으로 고르는 규칙을 더한 것입니다.  
> 나무들이 같은 질문만 반복하지 않아 투표가 더 안정적입니다.

**bias와 variance**

- bias (편향) — 언더핏: 모델이 단순해서 데이터의 복잡한 패턴을 인식 잘 못함
- variance (분산) — 오버핏: 모델이 데이터에 너무 민감, 새로운 데이터에는 성능이 떨어짐

> **쉽게 이해하기**  
> **편향(bias)** 이 크면 모델이 너무 단순해 **과소적합(underfitting)** 이 납니다.  
> **분산(variance)** 이 크면 학습 데이터에 과민해 **과적합**이 납니다.  
> 배깅·랜덤 포레스트는 분산을 줄이는 데 강점이 있습니다.

**Voting과 Bagging 차이점**

- Voting: 데이터셋의 크기가 작을 때, 결과를 해석하는 경우
- Bagging: 데이터셋의 크기가 클 때, 노이즈(이상치)에 강한 모델이 필요할 때

### (4) Boosting: 모델을 순차적으로 학습하면서 잘못 예측한 부분에 가중치를 더해가는 방식 ⇒ 이전 모델이 틀린 부분을 집중적으로 학습

- AdaBoost: 잘못 분류한 데이터에 가중치를 부여해서 순차적으로 학습한 뒤, 학습된 모델들을 통합 ⇒ 가중치 부여 방식은 오류율
- GradientBoost: 가중치 부여 방식 = 경사하강법
- XGBoost: GradientBoost의 느린 속도 개선 (파이썬 패키지, 속도 빠름) — 병렬 처리, 가지 치기, 규제 적용
- LightGBM: 리프 중심 분할로 학습 속도를 단축시키고 예측 성능 향상 ⇒ 손실 높은 리프를 기준으로 분할
- CatBoost (Category Boost): 범주형 데이터를 기존과 다른 방식으로 처리

> **쉽게 이해하기**  
> **부스팅(boosting)** 은 약한 모델을 순서대로 붙이며, 이전이 틀린 샘플에 가중치를 두고 다음 모델이 보완합니다.  
> 배깅은 병렬, 부스팅은 순차입니다.  
> **AdaBoost**, **Gradient Boosting**, **XGBoost**·**LightGBM**·**CatBoost**는 같은 아이디어의 실전 도구입니다.

**DT → Ensemble: Bagging / Boosting**

- Random Forest (병렬 학습, 과적합에 매우 강함) / Gradient Boosting (직렬·순차 학습, 정확도가 매우 높음)

**배깅 vs 부스팅 비교**

| 구분      | 배깅 (Random Forest 포함)          | 부스팅 (Gradient Boosting 등)     |
| --------- | ---------------------------------- | --------------------------------- |
| 학습 방식 | 병렬 (여러 모델을 한 번에)         | 순차 (하나씩 차례대로)            |
| 핵심 원리 | 여러 의견을 골고루 듣기 (집단지성) | 틀린 문제를 집중 공략 (오답 노트) |
| 목표      | 과적합 방지 (안정성)               | 정확도 향상 (성능)                |
| 속도      | 빠름 (동시 학습 가능)              | 상대적으로 느림 (앞 모델 대기)    |

- Voting = 다른 알고리즘을 묶는 방법
- Bagging = 같은 알고리즘을 병렬로 여러 개 학습 → 평균/투표
- Boosting = 약한 모델을 순차적으로 연결해서 점점 강화

> **쉽게 이해하기**  
> **보팅**은 다른 모델·같은 데이터, **배깅**은 같은 모델·다른 샘플·다수결, **부스팅**은 순차로 오차를 줄입니다.  
> 과적합을 줄이려면 배깅·랜덤 포레스트, 정확도를 더 올리려면 부스팅 계열을 자주 씁니다.
