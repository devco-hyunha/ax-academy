# 세션 07: 머신러닝 검증 방식 및 평가지표

> **이 세션이 하는 일 (쉬운 말)**  
> 모델을 만들었으면 “얼마나 잘했나?”를 숫자로 확인해야 합니다.  
> 오늘은 **검증(Validation)** 과 **테스트(Test)** 를 나누는 이유,  
> **교차 검증(Cross-Validation)** 으로 모의고사를 여러 번 보는 법,  
> 그리고 분류에서 가장 중요한 **혼동 행렬·정밀도·재현율**을  
> 쉬운 비유로 정리합니다.

---

## 1. 머신러닝 검증 방식

- 학습 → 모의고사(검증)를 보면서 → 수능(테스트)을 본다 → 평가지표
- **검증 (Validation)**: 최종 테스트를 보기 전, 모델 학습의 방향을 점검하고 학습 방식 변경하기 위해 학습 후에 진행하는 모의 테스트
- **테스트 (Test)**: 최종 테스트 / 오직 성능 측정을 위해서만 확인한다
- **평가지표 (Metric)**: 모델이 검증 및 최종 테스트를 진행했을 때, 모델의 성능 확인하기 위한 지표

> **쉽게 이해하기**  
> 공부 비유로 세 단계를 나눕니다.
>
> 1. **학습(Train)**: 교과서·문제집으로 공부
> 2. **검증(Validation)**: **모의고사** — 틀린 유형을 보고 공부법(하이퍼파라미터)을 바꿈
> 3. **테스트(Test)**: **수능** — 이미 답을 보고 공부하면 안 됨. **최종 성적만** 확인
>
> **평가지표(Metric)** = 그 성적표에 적히는 숫자(정확도, 정밀도 …).  
> 모의고사로 방향을 고치고, 수능 점수로 “진짜 실력”을 발표한다고 생각하면 됩니다.

### 교차 검증 (Cross-Validation)

- 모의 테스트의 신뢰성을 높이기 위해 한 번 검증하는 것이 아니라, 데이터를 여러 번 나누어 모델 성능을 평가하는 방법
- **K-fold**: 같은 모델을 여러 개 만든 후, 검증 데이터를 K개로 분할하여 검증을 여러 번 하는 것
- **Stratified K-fold**: Class (아파트, 주택) 불균형을 고려해 검증용 데이터의 구성 class 비율을 맞춰서 class 편향 학습을 방지하는 방법

> **쉽게 이해하기**  
> 모의고사를 **한 번만** 보면, 그번 시험 범위가 운 좋게/나쁘게 나올 수 있습니다.  
> **교차 검증(Cross-Validation)** = 데이터를 여러 덩어리로 나눠  
> “돌아가며 모의고사”를 여러 번 보고, 점수를 **평균** 내는 방법입니다.
>
> **K-fold**: 데이터를 K등분 → 한 조각을 검증, 나머지로 학습 → K번 반복.  
> 예: K=5면 5번 모의고사.
>
> **Stratified K-fold**: 클래스 비율까지 **골고루** 맞춘 K-fold.  
> 예: 전체의 90%가 “정상”, 10%가 “이상”이면,  
> 검증 조각에도 비슷한 비율이 들어가게 해서  
> “운 좋게 이상 케이스가 빠진 모의고사”를 막습니다.

## 2. 평가지표

- 모델이 학습을 끝내면 검증 및 최종 테스트를 진행한다. 이때 모델이 얼마나 잘 학습했는지 해석하기 위해 수치상으로 확인할 수 있는 것
- 모델이 수행하는 일에 따라서 평가지표가 달라진다

> **쉽게 이해하기**  
> 회귀(숫자 맞추기)와 분류(예/아니오)는 **성적 채점 방식**이 다릅니다.  
> 오늘은 **분류** 쪽 채점표 — 특히 혼동 행렬과 그에 기반한 지표 — 에 집중합니다.

### Confusion Matrix (혼동 행렬) — 분류 모델 평가지표

- 모델 예측값과 실제 값을 비교한다
- TP: Positive를 맞춘 경우
- FP: Positive를 틀린 경우 (실제는 Negative인데 Positive라고 함)
- FN: Negative를 틀린 경우 (실제는 Positive인데 Negative라고 함)
- TN: Negative를 맞춘 경우

> **쉽게 이해하기**  
> **혼동 행렬(Confusion Matrix)** = “실제 vs 예측”을 **네 칸**으로 정리한 표.  
> Positive를 “도둑이다 / 질병이다 / 스팸이다”처럼 **찾고 싶은 쪽**이라고 두면 쉽습니다.
>
> |  | 예측 Positive | 예측 Negative |
> |--|--|--|
> | 실제 Positive | **TP** (잘 잡음) | **FN** (놓침) |
> | 실제 Negative | **FP** (거짓 경보) | **TN** (잘 통과) |
>
> - **TP (True Positive)**: “맞다”고 했는데 정말 맞음 — 잘한 탐지
> - **FP (False Positive)**: “맞다”고 했는데 틀림 — **거짓 경보**
> - **FN (False Negative)**: “아니다”고 했는데 사실 맞음 — **놓침**
> - **TN (True Negative)**: “아니다”고 했는데 정말 아님 — 잘 걸러 냄
>
> 이름이 헷갈리면 이렇게 외우세요.  
> **False** = 틀림, **Positive/Negative** = 모델이 뭐라고 **외쳤는지**.

### 정확도 (Accuracy)

- 정확도 = (TP + TN) / (TP + TN + FP + FN)
- 단점: 전체 데이터 중 단순히 맞은 개수만 보기 때문에, 데이터의 분포가 불균형할 경우 모델이 잘 분류하는지 정확도만으로 판단하기 힘들다 ⇒ 불균형한 데이터에 취약
- 그래서 정밀도도 확인해야 함

> **쉽게 이해하기**  
> **정확도(Accuracy)** = 전체 중에서 **맞춘 비율**.  
> (잘한 것 TP+TN) / (전부).
>
> 함정: 질병이 1%만 있는 데이터에서  
> “무조건 정상”이라고만 해도 정확도 99%가 나옵니다.  
> → **불균형 데이터**에서는 정확도만 믿으면 위험합니다.  
> 그래서 정밀도·재현율을 같이 봅니다.

### 정밀도·재현율·F1

- **정밀도 (Precision)**: 양성 예측의 정확도 = 양성을 맞춘 개수 / 모델이 양성이라고 예측한 개수
- **재현율 (Recall)**: 양성을 맞춘 개수 / 실제 양성 개수
- **조화평균**: 어느 한쪽이 너무 작아지면 전체 결과도 작아지게 하는 평균 → 정밀도와 재현율을 조합한 평가지표 (F1)

> **쉽게 이해하기**  
> 두 질문을 구분하세요.
>
> - **정밀도(Precision)** = “모델이 **양성이라고 외친 것** 중에, 진짜 양성이 얼마나 되나?”  
>   → **거짓 경보(FP)** 를 싫어할 때 중요  
>   식: \( \mathrm{Precision} = \frac{TP}{TP + FP} \)
>
> - **재현율(Recall)** = “실제로 양성인 것 중에, 모델이 **얼마나 찾아냈나?**”  
>   → **놓침(FN)** 을 싫어할 때 중요  
>   식: \( \mathrm{Recall} = \frac{TP}{TP + FN} \)
>
> 비유:
>
> - 정밀도↑ = “경보를 울리면 거의 진짜” (신중)
> - 재현율↑ = “진짜는 거의 다 잡음” (민감)
>
> **F1** = 정밀도와 재현율의 **조화평균**.  
> 한쪽만 높고 다른 쪽이 바닥이면 F1도 낮아집니다.  
> “둘 다 어느 정도 괜찮아야 한다”는 성적표입니다.

### 예시로 본 중요도

**예) 도둑 탐지 시스템**

- FP: 도둑이라고 예측했지만 틀린 경우 / FN: 도둑이 아니라고 예측했지만 틀린 경우
- 정밀도: FP를 낮추는 것이 관건 / 재현율: FN을 낮추는 것이 관건
- ⇒ FN을 낮추는 것이 더 중요한 상황

> **쉽게 이해하기**  
> 도둑을 **놓치는 것(FN)** 이 더 무섭습니다.  
> 가끔 오경보(FP)가 나더라도, 진짜 도둑은 잡고 싶은 상황 → **재현율**을 우선.

**예) 스팸 메일 필터 시스템**

- FP: 스팸이라고 예측했지만 틀린 경우 / FN: 스팸이 아니라고 예측했지만 틀린 경우
- ⇒ FP를 낮추는 것이 더 중요한 상황 (중요한 메일이 스팸으로 분류되면 안 됨)

> **쉽게 이해하기**  
> 중요한 메일이 **스팸함으로 가는 것(FP)** 이 더 치명적입니다.  
> 스팸 몇 통이 받은편지함에 남는 것(FN)보다 나쁨 → **정밀도**를 우선.

```text
혼동 행렬 네 칸 → 정확도 / 정밀도 / 재현율 / F1
불균형 데이터면 정확도만 보지 말 것
“놓치면 위험” → 재현율(FN↓)
“잘못 잡으면 위험” → 정밀도(FP↓)
```
