# 세션 07: 머신러닝 검증 방식 및 평가지표

> **이 세션이 하는 일 (쉬운 말)**  
> 모델을 만들었으면 “얼마나 잘했나?”를 숫자로 확인해야 합니다.  
> 오늘은 **검증(Validation)** 과 **테스트(Test)** 를 나누는 이유,

> 쉬운 비유로 정리합니다.

---

## 1. 머신러닝 검증 방식

- 학습 → 모의고사(검증)를 보면서 → 수능(테스트)을 본다 → 평가지표
- **검증 (Validation)**: 최종 테스트를 보기 전, 모델 학습의 방향을 점검하고 학습 방식 변경하기 위해 학습 후에 진행하는 모의 테스트
- **테스트 (Test)**: 최종 테스트 / 오직 성능 측정을 위해서만 확인한다
- **평가지표 (Metric)**: 모델이 검증 및 최종 테스트를 진행했을 때, 모델의 성능 확인하기 위한 지표

> **쉽게 이해하기**  
> 성능은 **학습(Train) → 검증(Validation) → 테스트(Test)** 순으로 나눠 봅니다.  
> 학습은 데이터로 규칙을 만듭니다. 검증은 공부법(하이퍼파라미터)을 고칠 **모의고사**입니다.  
> 테스트는 답을 미리 보지 않은 **최종 시험**으로, 점수만 확인합니다.  
> **평가지표(Metric, 성적표 숫자)** 는 정확도·정밀도처럼 각 단계에서 적히는 값입니다.

### 교차 검증 (Cross-Validation)

- 모의 테스트의 신뢰성을 높이기 위해 한 번 검증하는 것이 아니라, 데이터를 여러 번 나누어 모델 성능을 평가하는 방법
- **K-fold**: 같은 모델을 여러 개 만든 후, 검증 데이터를 K개로 분할하여 검증을 여러 번 하는 것
- **Stratified K-fold**: Class (아파트, 주택) 불균형을 고려해 검증용 데이터의 구성 class 비율을 맞춰서 class 편향 학습을 방지하는 방법

> **쉽게 이해하기**  
> **교차 검증(Cross-Validation)** 은 데이터를 여러 덩어리로 나눠 검증을 반복하고, 점수 **평균**을 내는 방법입니다.  
> 한 번만 보면 운에 따라 점수가 흔들릴 수 있습니다.  
> **K-fold**: K조각으로 나눈 뒤, 조각 하나를 검증·나머지로 학습을 K번 돌립니다.  
> **Stratified K-fold**: 각 조각에 **클래스(종류) 비율**이 전체와 비슷하게 들어가도록 맞춘 K-fold입니다.

## 2. 평가지표

- 모델이 학습을 끝내면 검증 및 최종 테스트를 진행한다. 이때 모델이 얼마나 잘 학습했는지 해석하기 위해 수치상으로 확인할 수 있는 것
- 모델이 수행하는 일에 따라서 평가지표가 달라진다

> **쉽게 이해하기**  
> 오늘은 **분류(Classification, 예/아니오 맞추기)** 채점표만 다룹니다.  
> **회귀(Regression, 숫자 맞추기)** 는 다른 지표를 씁니다.

### Confusion Matrix (혼동 행렬) — 분류 모델 평가지표

- 모델 예측값과 실제 값을 비교한다
- TP: Positive를 맞춘 경우
- FP: Positive를 틀린 경우 (실제는 Negative인데 Positive라고 함)
- FN: Negative를 틀린 경우 (실제는 Positive인데 Negative라고 함)
- TN: Negative를 맞춘 경우

> **쉽게 이해하기**  
> **혼동 행렬(Confusion Matrix)** 은 실제와 예측을 **네 칸** 표로 모은 것입니다.  
> **Positive** 는 찾고 싶은 쪽(질병, 스팸 등)입니다.
>
> |  | 예측 Positive | 예측 Negative |
> |--|--|--|
> | 실제 Positive | **TP** (잘 잡음) | **FN** (놓침) |
> | 실제 Negative | **FP** (거짓 경보) | **TN** (잘 통과) |
>
> - **TP (True Positive, 참 양성)**: 양성이라 맞게 예측
> - **FP (False Positive, 거짓 양성)**: 양성이라 했으나 틀림 — **거짓 경보**
> - **FN (False Negative, 거짓 음성)**: 음성이라 했으나 놓침
> - **TN (True Negative, 참 음성)**: 음성이라 맞게 예측
>
> **False** 는 틀림, **Positive/Negative** 는 모델이 한 **예측 라벨**입니다.

### 정확도 (Accuracy)

- 정확도 = (TP + TN) / (TP + TN + FP + FN)
- 단점: 전체 데이터 중 단순히 맞은 개수만 보기 때문에, 데이터의 분포가 불균형할 경우 모델이 잘 분류하는지 정확도만으로 판단하기 힘들다 ⇒ 불균형한 데이터에 취약
- 그래서 정밀도도 확인해야 함

> **쉽게 이해하기**  
> **정확도(Accuracy)** 는 전체 가운데 맞춘 비율입니다. (TP+TN)/전체  
> **불균형 데이터** 에서는 “항상 정상”만 외쳐도 정확도가 높게 나올 수 있습니다.  
> 이때는 **정밀도(Precision)** · **재현율(Recall)** 을 함께 봅니다.

### 정밀도·재현율·F1

- **정밀도 (Precision)**: 양성 예측의 정확도 = 양성을 맞춘 개수 / 모델이 양성이라고 예측한 개수
- **재현율 (Recall)**: 양성을 맞춘 개수 / 실제 양성 개수
- **조화평균**: 어느 한쪽이 너무 작아지면 전체 결과도 작아지게 하는 평균 → 정밀도와 재현율을 조합한 평가지표 (F1)

> **쉽게 이해하기**  
> **정밀도(Precision)** 와 **재현율(Recall)** 은 질문이 다릅니다.  
> 정밀도는 “양성이라고 한 것 중 진짜 양성 비율”입니다. 거짓 경보(FP)를 줄일 때 중요합니다.  
>   \( \mathrm{Precision} = \frac{TP}{TP + FP} \)  
> 재현율은 “실제 양성 중 모델이 찾은 비율”입니다. 놓침(FN)을 줄일 때 중요합니다.  
>   \( \mathrm{Recall} = \frac{TP}{TP + FN} \)  
> **F1** 은 둘의 **조화평균**입니다. 한쪽만 높으면 F1도 낮아집니다.

### 예시로 본 중요도

**예) 도둑 탐지 시스템**

- FP: 도둑이라고 예측했지만 틀린 경우 / FN: 도둑이 아니라고 예측했지만 틀린 경우
- 정밀도: FP를 낮추는 것이 관건 / 재현율: FN을 낮추는 것이 관건
- ⇒ FN을 낮추는 것이 더 중요한 상황

> **쉽게 이해하기**  
> 도둑을 놓치는 것(FN)이 더 위험하면 **재현율(Recall)** 을 우선합니다.  
> 가끔 오경보(FP)가 있어도 진짜는 잡는 쪽을 택합니다.

**예) 스팸 메일 필터 시스템**

- FP: 스팸이라고 예측했지만 틀린 경우 / FN: 스팸이 아니라고 예측했지만 틀린 경우
- ⇒ FP를 낮추는 것이 더 중요한 상황 (중요한 메일이 스팸으로 분류되면 안 됨)

> **쉽게 이해하기**  
> 중요 메일이 스팸함으로 가는 것(FP)이 더 위험하면 **정밀도(Precision)** 를 우선합니다.

```text
혼동 행렬 네 칸 → 정확도 / 정밀도 / 재현율 / F1
불균형 데이터면 정확도만 보지 말 것
“놓치면 위험” → 재현율(FN↓)
“잘못 잡으면 위험” → 정밀도(FP↓)
```
