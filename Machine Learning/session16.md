# 세션 16: 머신 러닝 5-1 — 트리 계열 회귀기

<!-- session-nav -->
**이동:** [← 세션 15](./session15.md) · [세션 17 →](./session17.md)

session15가 선형·규제·로지스틱을 다뤘다면, 이번 세션은 **트리를 이용해 연속 숫자를 맞추는 회귀기(Regressor)** 네 가지를 비교합니다.

> **이 세션이 하는 일 (쉬운 말)**  
> 지난번에는 직선·평면으로 숫자를 맞추거나, 로지스틱으로 예/아니오를 가렸습니다.  
> 오늘은 **결정 트리(Decision Tree) 계열**로 “집값·기온처럼 연속 숫자”를 예측하는 방법을 봅니다.  
> 한 그루 트리부터, 여러 그루를 모아 쓰는 랜덤 포레스트·부스팅·XGBoost까지  
> **어떻게 다르고 무엇이 강한지**를 쉬운 말로 정리합니다.  
> 핵심만 먼저 기억하면 됩니다: 같은 “나무” 아이디어라도  
> **한 그루 / 여러 그루를 동시에 / 여러 그루를 차례로** 쓰느냐가 다릅니다.

---

## 1. Classifier vs Regressor

| 구분 | 하는 일 | 예시 |
| ---- | ------- | ---- |
| **Classifier** | 어느 **그룹**인지 가림 | 스팸? / 기온 높음·낮음? |
| **Regressor** | **연속 수치**를 예측 | 집값? / 내일 기온 몇 도? |

이번 세션의 `*Regressor`들은 모두 **연속 숫자를 맞추는 쪽**입니다.  
이름에 Tree·Forest·Boosting이 있어도, 끝이 Regressor면 “분류”가 아니라 “숫자 예측”입니다.

> **쉽게 이해하기**  
> 이름 끝 **Classifier(분류기)** 는 바구니(그룹)를 고르고, **Regressor(회귀기)** 는 연속 숫자를 맞춥니다.  
> 분류 트리 잎(Leaf, 맨 끝 칸)은 **다수결**, 회귀 트리 잎은 그 칸 데이터 **평균**이 예측값입니다.  
> 이번 네 모델은 모두 `*Regressor`이므로 숫자 맞추기라고 기억하시면 됩니다.

---

## 2. DecisionTreeRegressor

- 특정 기준으로 데이터를 계속 나눠 **Leaf(잎)**에 도달
- 그 Leaf에 모인 데이터의 **평균**이 예측값
- 트리를 **너무 깊게** 키우면 학습 데이터에만 맞춰져 **과적합(Overfitting)**이 쉬움

> **쉽게 이해하기**  
> **결정 트리(Decision Tree)** 는 예·아니오 질문으로 데이터를 잘게 나누는 방법입니다.  
> 맨 끝 **Leaf(잎)** 에 모인 가격의 **평균**이 그 구역 집의 예측값입니다.  
> 질문을 너무 많이 하면 학습 데이터만 외워 **과적합(overfitting, 새 데이터에서 약함)** 이 되므로 **깊이(depth)** 제한이 필요합니다.

---

## 3. RandomForestRegressor

- **배깅(Bagging)**: 무작위 샘플로 **독립** 결정 트리를 여러 개 학습
- 각 트리 예측의 **산술 평균**이 최종 예측
- 한 그루보다 **안정적**이고, 과적합에 **강한** 편

> **쉽게 이해하기**  
> **랜덤 포레스트(Random Forest)** 는 데이터를 무작위로 뽑아 **서로 다른 트리** 여러 그루를 키운 뒤 예측 **평균**을 냅니다.  
> **배깅(Bagging, 표본을 여러 번 뽑아 합치기)** 방식이라 나무끼리 독립적이고 병렬로 학습할 수 있습니다.  
> 한 그루보다 안정적이고 과적합에 강한 편입니다.

---

## 4. GradientBoostingRegressor

- **부스팅(Boosting)**: 트리를 **순차**로 쌓으며 앞 모델의 실수를 보정
- 앞 단계의 **잔차(Residual, 틀린 양)**를 다음 트리가 학습
- 모든 나무 결과를 **합산**해 최종 예측
- 성능은 우수한 편이나, 순차 학습이라 **느리고** 파라미터 조정이 **까다로움**

> **쉽게 이해하기**  
> **그래디언트 부스팅(Gradient Boosting)** 은 트리를 **차례로** 쌓으며 앞 모델의 **잔차(실제 − 예측)** 를 다음이 고칩니다.  
> 오답에만 집중해 정확도는 높은 편이나 순차라 **느리고** 설정 조절이 까다롭습니다.  
> 최종 예측은 모든 나무 결과를 **더합니다**.

---

## 5. XGBRegressor

- Gradient Boosting의 **속도·과적합** 문제를 개선한 업그레이드
- **성능과 속도**를 함께 노리는 쪽으로 자주 쓰임

> **쉽게 이해하기**  
> **XGBRegressor**는 **XGBoost(극단적 그래디언트 부스팅)** 의 회귀용입니다.  
> 부스팅과 같은 오답 수정 흐름에 계산 속도와 **과적합** 방지 장치를 더한 실전형입니다.

---

## 6. 네 모델 비교표

| 모델 | 방식 | 비유 | 장점 |
| ---- | ---- | ---- | ---- |
| DecisionTree | 단일 모델 | 똑똑한 전문가 1명 | 이해하기 쉬움 |
| RandomForest | 병렬 (Bagging) | 평범한 사람 100명의 투표 | 안정적임 |
| GradientBoosting | 직렬 (Boosting) | 오답 노트를 쓰며 공부 | 정확도가 매우 높음 |
| XGBoost | 최적화 Boosting | 슈퍼 컴퓨터를 가진 학생 | 매우 빠르고 매우 정확함 |

> **쉽게 이해하기**  
> 설명이 필요하면 DecisionTree, 안정이 필요하면 RandomForest, 점수를 더 뽑으려면 GradientBoosting 또는 XGBoost를 고려합니다.
>
> | 선택 | 한 줄 감각 |
> | ---- | ---------- |
> | DecisionTree | 설명은 쉽지만 혼자라 과적합에 약할 수 있음 |
> | RandomForest | 여러 트리 예측을 동시에 모아 평균 → 안정 |
> | GradientBoosting | 오답을 차례로 고침 → 정확도↑, 느리고 조절 어려움 |
> | XGBoost | 부스팅을 더 빠르고 튼튼하게 만든 실전형 |
>
> 네 모델 모두 회귀(`*Regressor`)이며, 나무 개수와 순서만 다릅니다.

## 한눈에 정리

```text
[Classifier] 그룹 분류     vs  [Regressor] 연속 수치 예측  ← 이번 주제는 오른쪽

DecisionTreeRegressor
  분할 → Leaf 평균 = 예측 / 깊으면 과적합 주의

RandomForestRegressor (Bagging, 병렬)
  독립 트리 여러 개 → 예측 산술 평균 / 안정·과적합에 강함

GradientBoostingRegressor (Boosting, 직렬)
  잔차를 다음 트리가 학습 → 결과 합산 / 성능↑ · 느림 · 파라미터 까다로움

XGBRegressor
  GB의 속도·과적합을 개선 / 성능 + 속도
```

2. DecisionTreeRegressor의 Leaf에서 예측값은 어떻게 정해지나요?
3. RandomForest는 여러 트리의 예측을 어떻게 합치나요?
4. Gradient Boosting이 “순차”인 이유는 무엇인가요?
5. XGBRegressor를 한 줄로 말하면?

<details>
<summary>답 보기</summary>

1. Classifier는 그룹 분류, Regressor는 연속 수치 예측.
2. Leaf에 모인 데이터의 **평균**.
3. 각 트리 예측의 **산술 평균**(배깅).
4. 앞 모델의 **잔차(틀린 양)**를 다음 트리가 이어서 배우기 때문.
5. Gradient Boosting을 **더 빠르고 과적합에 강하게** 다듬은 회귀기.

</details>
