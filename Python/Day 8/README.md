## 1. 파이썬 동시성/병렬성 처리 모델 비교 (Quick Reference)

| 구분 | 비동기 프로그래밍 (`asyncio`) | 멀티스레딩 (`threading`) | 멀티프로세싱 (`multiprocessing`) |
| :--- | :--- | :--- | :--- |
| **구현 방식** | 단일 스레드 + 이벤트 루프 | 복수 OS 스레드 (경량 프로세스) | 복수 독립 프로세스 (완전한 분리) |
| **스케줄링** | 협력적(Cooperative, `await`로 자발적 양보) | 선점형(Preemptive, OS 스케줄러가 전환) | 선점형(OS 프로세스 스케줄러) |
| **GIL 영향** | 영향 없음 (단일 스레드 내 순차 전환) | **GIL 영향 받음** (한 번에 1개 스레드만 바이트코드 실행) | **GIL 우회 가능** (프로세스마다 독립 인터프리터 소유) |
| **적합한 작업** | **대량의 네트워크/웹 API I/O** (수천 개 연결) | **파일/소켓 I/O 바운드 작업** | **CPU 연산 집약적 작업** (머신러닝, 대용량 수치 계산) |
| **메모리 오버헤드** | 극소 (코루틴당 수 KB) | 보통 (스레드당 수 MB 스택) | 큼 (프로세스 메모리 공간 복제) |

## 2. Day 8 핵심 복습 포인트 (Cheat Sheet)

1. **`async def`와 `await`**:
   - `async def`로 정의된 함수는 호출 시 즉시 실행되지 않고 코루틴 객체를 생성합니다.
   - `await`는 코루틴 내부에서만 사용 가능하며, 실행을 일시 정지하고 제어권을 이벤트 루프에 넘깁니다.
2. **`asyncio.gather(*coros)`**:
   - 전달된 여러 코루틴을 동시에(Concurrently) 스케줄링하여 실행 시간을 획기적으로 단축합니다.
3. **스레드 인자 전달 시 단일 튜플(`args=(arg,)`)**:
   - 스레드 대상 함수에 단일 인자를 전달할 때는 반드시 끝에 쉼표(`,`)를 붙여 튜플 타입임을 명시해야 문자열 쪼개짐 오류를 방지할 수 있습니다.
4. **`start()` vs `join()`의 역할 분리**:
   - `start()`는 새 스레드를 가동시키고 메인 코드는 즉시 다음 줄로 이동합니다.
   - `join()`은 대상 스레드가 작업을 완료할 때까지 현재 스레드의 진행을 멈추고 기다립니다.
   - 여러 스레드를 병렬로 처리하려면 모든 스레드를 `start()`한 뒤, 별도의 루프에서 순서대로 `join()`해야 합니다.
5. **스케줄링의 비결정성 (Non-deterministic)**:
   - 스레드의 CPU 점유 순서와 종료 시점은 OS 스케줄러에 종속되므로, 코드상의 `start()` 호출 순서와 실제 완료 순서는 일치하지 않을 수 있습니다.
